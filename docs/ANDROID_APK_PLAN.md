# Android APK Plan — Angle Detector (Capacitor)

**Status:** plan only. No toolchain installed here, no code changed for this yet.
**Strategy:** Capacitor wraps the existing React/Vite app. No separate Android
implementation — the web app is reused as-is inside a native WebView shell.

## 1. Minimum toolchain (Capacitor 7 route — conservative)

| Component | Version | Notes |
|---|---|---|
| JDK | 17 (Temurin or Oracle) | Capacitor 7 = JDK 17. (Capacitor 8 would need JDK 21; not recommended yet.) |
| Android SDK | cmdline-tools + platform-tools + `platforms;android-35` + `build-tools;35.0.0` | `sdkmanager` install; ~1–2 GB download |
| Gradle | 8.11.1 via wrapper | Generated by `npx cap add android` (AGP 8.7.2) |
| Node | 20+ | Already present in dev environments |
| `minSdkVersion` / `compileSdkVersion` / `targetSdkVersion` | 23 / 35 / 35 | Capacitor 7 defaults; Moto G Power (Android 16) is API 36 — targetSdk 35 is fine |

**Can it be built in this environment? No.** No JDK, no Android SDK, no Gradle,
no emulator/adb here, and toolchain installation is explicitly not approved yet.
The plan below is for a machine with the toolchain (dev workstation or CI).

## 2. Code changes required before packaging

All are small, web-side, and reversible. None touch geometry/measurement/vision.

1. **Offline bundling (required).** `index.html` currently loads the Tailwind Play CDN
   and an `aistudiocdn.com` import map. An APK must work offline:
   - The production JS bundle is already self-contained (verified: zero external
     module refs — React etc. are inlined by Vite).
   - Vendor Tailwind: generate the utility CSS at build time (Tailwind v4 compiler
     against the repo's class list — proven working in Session 006/007 harness) and
     inline it or ship as a local `assets/tailwind.css`. Delete the CDN `<script>`
     and the import map from `index.html`.
2. **Camera permission.** `AndroidManifest.xml`: `<uses-permission android:name="android.permission.CAMERA" />`
   + `<uses-feature android:name="android.hardware.camera" android:required="true" />`.
   Capacitor's bridge forwards the WebView `getUserMedia` permission request to the
   Android runtime permission prompt. The app's existing `getUserMedia` error path
   ("Could not access camera … or use Open Photo") already handles denial.
3. **Safe-area insets.** The app does not use `env(safe-area-inset-*)`. Add
   `padding-bottom: env(safe-area-inset-bottom)` to the bottom readout bar and
   `env(safe-area-inset-top)` to the header so gesture-navigation bars don't cover
   controls. Pure CSS.
4. **Rotation.** Capacitor's default `android:configChanges="orientation|screenSize|keyboardHidden|smallestScreenSize|screenLayout|uiMode"`
   prevents activity restarts; the app already re-lays-out via ResizeObserver.
   Verify on device that a mid-measurement rotation keeps points aligned.
5. **Export fallback (verify on device).** The app saves via `<a download>` from a
   blob URL. Test in the WebView first — if the download doesn't land in the
   gallery/Downloads, use `@capacitor/filesystem` (write PNG to app storage) +
   `@capacitor/share` as the fallback. No change until the device test says so.
6. **Photo selection.** `<input type="file" accept="image/*">` opens the system photo
   picker — no storage permission needed on Android 13+ (Photo Picker). Already the
   app's primary fixture path; unchanged.

## 3. Build steps (once, on a tooled machine)

```bash
npm install                    # existing web deps
npm run build                  # web build (after §2 changes)
npm i @capacitor/core @capacitor/cli
npx cap init "Angle Detector" com.ingenuous.angledetector --web-dir=dist
npx cap add android            # generates android/ (Gradle wrapper, manifest)
# edit android/app/src/main/AndroidManifest.xml (§2.2), variables.gradle SDK levels
npx cap sync android
cd android && ./gradlew assembleDebug
# → android/app/build/outputs/apk/debug/app-debug.apk
adb install -r app-debug.apk   # on the Moto G Power with USB debugging
```

`android/` is generated native scaffolding — commit it or gitignore it per owner
preference (Capacitor docs: either works; committing pins the native config).

## 4. Open questions for the device test

- Does `<a download>` export work in the WebView, or is the Filesystem fallback needed?
- Does `getUserMedia` deliver a usable rear-camera stream (resolution, focus)?
- Any WebView-specific touch/pointer quirks vs Chrome?
- Exact safe-area padding needed on the Moto G Power's gesture bar.

## 5. What is NOT needed

- No rewrite, no native camera code, no new measurement code.
- No Play Store signing yet (debug APK via `adb install` is enough for acceptance).
- No background services, no network permissions (fully offline after §2.1).
